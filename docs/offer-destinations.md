# Посадочные страницы оффера

`OfferDestination` — разрешённая страница одного оффера. Комиссия, hold, доступ партнёров, окно атрибуции и compliance остаются на `Offer`. Страница не является отдельным оффером.

`Product.url` сохраняется. Для новых записей источник адреса новой ссылки — активная страница (`OfferDestination.url`). Если страница основная, её URL синхронизируется в `Product.url`. Уже созданная `TrackingLink.destination_url` — снимок и не переписывается.

## Данные

Таблица `offer_destinations` и nullable `tracking_links.offer_destination_id` добавляются миграцией `036`.

- Один primary на оффер: частичный уникальный индекс `uq_offer_destinations_one_primary`.
- Один и тот же URL не повторяется внутри оффера.
- Составной внешний ключ `(offer_destination_id, offer_id)` не даёт ссылке оффера A указывать на страницу оффера B.
- Страница не удаляется физически. `DELETE` отключает её.
- Ссылки без `offer_destination_id` работают как раньше.

Backfill не входит в транзакцию миграции. Его выполняет `backfill_legacy_destinations`: для оффера без страниц и с безопасным HTTPS `Product.url` создаётся одна primary-страница. Неподходящий URL пропускается с причиной, адрес не переписывается. Тот же шаг выполняется точечно при чтении страниц оффера.

## API

Бизнес, владелец оффера:

- `GET/POST /api/v1/business/offers/{offerId}/destinations`
- `PATCH/DELETE /api/v1/business/offers/{offerId}/destinations/{destinationId}`

Партнёр видит только активные страницы оффера, который ему и так виден:

- `GET /api/v1/partner/offers/{offerId}/destinations`

Создание партнёрской ссылки принимает необязательные `offer_destination_id` и `without_campaign`. Без них сохраняется прежний сценарий: основная страница или legacy `Product.url`, кампания создаётся автоматически. Произвольный `destination_url` партнёра по-прежнему не подменяет выбранную страницу. Бизнес по-прежнему может создать собственную ссылку с отдельным URL; такая ссылка остаётся business-owned и без `offer_destination_id`.

Отключение страницы не делает `UPDATE` по всем ссылкам. Новые переходы по ссылкам с этим `offer_destination_id` не создают `rqcid` и `Click`. Ссылка, которую владелец сам отключил, при повторном включении страницы не включается.

## Tracker

Java-редирект по-прежнему ищет ссылку одним запросом. К нему добавлен `LEFT JOIN offer_destinations`. Редирект идёт на `tracking_links.destination_url`. Если связанная страница не `active`, ответ тот же, что у отключённой ссылки: статическая 404. `Sec-Purpose: prefetch/prerender` по-прежнему завершается до поиска ссылки и возвращает 204.

Python-маршрут `/go/{shortCode}` использует тот же признак доступности и не ходит в отдельный сервис.

## Compliance

Отдельного контура проверки страниц в коде не было. Страница использует категорию оффера:

- gambling-категории (`ONLINE_CASINO`, `SLOTS`, `LIVE_CASINO`, `POKER`, `BINGO`, `LOTTERY`, `SOCIAL_CASINO`) нельзя опубликовать как страницу;
- betting-категории (`SPORTSBOOK`, `ESPORTS_BETTING`, `FANTASY_SPORTS`, `PREDICTION_PLATFORMS`) не получают новую страницу при доступе `open`.

Смена URL betting-страницы возвращает `compliance_review_required`. Очереди ручной модерации в платформе нет: страница не прячется сама, чтобы не создать тупиковое состояние. Это зафиксировано как остаточный риск.

URL страницы проходит текущую проверку домена бизнеса и отдельные запреты: только HTTPS, без учётных данных в URL, без опасного порта, без частных и служебных адресов. Для доменов вне документации выполняется DNS-проверка из существующего SSRF-контура. Query string сохраняется.

## Развёртывание

1. Миграция `036`. Старые процессы её не читают.
2. API. Старые клиенты создают офферы и ссылки без новых полей.
3. Tracker. Его нужно выкатывать после миграции: запрос содержит `LEFT JOIN offer_destinations`.
4. Frontend.
5. `backfill_legacy_destinations` для уже существующих офферов. Повторный запуск безопасен.

Откат приложения не требует удаления таблицы. Откат tracker до версии без JOIN возможен только вместе с отказом от колонки, поэтому при откате tracker оставляют совместимую сборку либо не откатывают схему. Деструктивный rollback схемы не используется.

Продакшен-миграцию и выкладку без отдельного разрешения не выполнять.
